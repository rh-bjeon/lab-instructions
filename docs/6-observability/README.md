# 모듈 6 - AI 감시자

> 관측성(observability) 없이 운영 환경에서 AI를 실행하는 것은 눈을 가리고 수업하는 것과 같습니다. 학생들이 잘 따라오는지, 어려움을 겪는지, 이미 교실을 떠났는지조차 알 수 없습니다. 이제 Canopy의 상태를 파악하고 신뢰성을 유지하는 데 필요한 계측 체계를 갖추겠습니다. 📊

# 🧑‍🍳 모듈 소개

요약과 RAG 기능을 갖춘 Canopy를 구축했지만 운영 환경에서도 제대로 동작하는지는 어떻게 알 수 있을까요? 이 모듈에서는 AI 애플리케이션을 관찰 가능한 시스템으로 바꾸는 관측성의 세 가지 핵심 요소를 다룹니다.

OpenShift AI의 관측성 스택을 사용해 성능을 수치로 보여주는 메트릭, 시스템 동작을 기록하는 로그, 분산 시스템을 통과하는 요청의 경로를 보여주는 트레이스를 수집합니다. 사용자 피드백으로 개선 주기를 완성하는 방법도 배웁니다. 좋아요와 싫어요를 수집하고 부정적인 피드백을 평가 사례로 전환하며, A/B 테스트로 프롬프트를 비교해 데이터에 근거한 결정을 내립니다. 모듈을 마치면 Canopy의 상태를 한눈에 보여주는 대시보드와 피드백 기반 개선 흐름을 구축하고 문제를 빠르게 분석할 수 있습니다.

# 🔮 학습 목표

* 관측성의 세 가지 핵심 요소와 운영 AI 시스템에서 필요한 이유를 설명할 수 있습니다.
* OpenTelemetry, Prometheus, MLflow를 사용해 OpenShift AI의 관측성 스택을 배포하고 구성할 수 있습니다.
* PromQL로 메트릭을 조회해 Canopy의 성능과 리소스 사용량을 모니터링할 수 있습니다.
* AI 관련 메트릭과 시스템 상태를 시각화하는 Grafana 대시보드를 만들 수 있습니다.
* OpenShift 로깅 스택으로 로그를 분석해 문제를 해결하고 사용자 상호작용을 이해할 수 있습니다.
* 요청 경로를 추적해 병목 구간과 지연 원인을 찾을 수 있습니다.
* 사용자 피드백을 수집하고 부정적인 신호를 평가 데이터셋으로 내보내 프롬프트를 체계적으로 개선할 수 있습니다.
* A/B 테스트로 프롬프트 후보를 비교하고 더 나은 버전을 승격할 수 있습니다.

# 🔨 이 모듈에서 사용하는 도구

* **OpenTelemetry Collector(OTel)**: AI 워크로드의 텔레메트리 데이터를 수집하는 벤더 중립적 표준
* **Prometheus**: 메트릭을 저장하고 알림을 처리하는 시계열 데이터베이스
* **Grafana**: 메트릭을 대시보드로 시각화하는 플랫폼
* **LokiStack**: OpenShift와 통합된 확장형 로그 수집 시스템
* **OpenShift User Workload Monitoring**: 애플리케이션 메트릭과 모델 성능을 추적하도록 미리 구성된 모니터링 스택
