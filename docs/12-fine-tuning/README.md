# 🧑‍🍳 모듈 소개

지금까지 Canopy의 모델을 속도와 비용 측면에서 최적화했습니다. 아직 개선할 수 있는 부분이 하나 남았습니다. 바로 **프롬프트 자체**입니다.

학생이 질문할 때마다 소크라테스식 튜터의 행동을 설명하는 긴 시스템 프롬프트도 함께 전송됩니다. 정답을 바로 알려주지 않고 유도 질문을 하며, 학생의 노력을 격려하고 좌절에 대응하라는 지침입니다. 원하는 대로 동작하지만 비용과 지연 시간이 늘어나고 탈옥(jailbreak) 공격에도 취약합니다.

이번 모듈에서는 긴 프롬프트에 의존하는 대신 소크라테스식 교육 방식을 모델 자체에 학습시키는 방법을 다룹니다. 합성 데이터 생성(synthetic data generation)과 LoRA 어댑터, 파인튜닝 워크플로를 배웁니다.

**핵심 질문:** *매번 행동을 설명하는 대신 그 행동을 모델에 학습시킬 수 있을까?*

# 🔮 학습 목표

* **파인튜닝 시점 판단하기** — 프롬프트 엔지니어링의 한계를 파악하기
* **합성 데이터 생성 이해하기** — SDG Hub가 문서에서 학습 예제를 만드는 방식 이해하기
* **학습 데이터셋 이해하기** — 모델이 요구하는 형식과 그 이유 알아보기
* **LoRA 이해하기** — 어댑터가 효율적인 파인튜닝을 가능하게 하는 방식 알아보기
* **평가하기** — 파인튜닝한 모델이 원하는 행동을 학습했는지 검증하기
* **운영 배포 계획하기** — 베이스 모델과 LoRA 어댑터를 함께 서빙하기

# 🔨 이 모듈에서 사용하는 도구

| 도구 | 역할 |
|------|------|
| **Docling** | PDF, 슬라이드, 문서를 처리하기 쉬운 Markdown으로 변환 |
| **SDG Hub** | LLM 기반 파이프라인으로 합성 학습 데이터 생성 |
| **Training Hub** | 최적화된 백엔드(Unsloth)로 LoRA 파인튜닝 수행 |
| **lm-evaluation-harness** | 파인튜닝 모델을 기준 모델과 비교해 벤치마크 |
| **vLLM** | 베이스 모델과 LoRA 어댑터를 동적으로 서빙 |
| **Argo CD** | 파인튜닝한 모델을 GitOps로 배포 |
